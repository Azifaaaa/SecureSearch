🔐 AES-256-GCM Encryption

What is AES-256-GCM?

AES-GCM (Galois/Counter Mode) is an authenticated encryption scheme that provides both confidentiality and data authenticity in a single operation.

AlgorithmAES-256-GCM
Key size256 bits (32 bytes)
Nonce size96 bits (12 bytes), random per encryption
Auth tag128 bits (16 bytes), appended to ciphertext
AADrecord_id + encryption version (binds ciphertext to record)
LibraryPython cryptography (pyca)
# Encryption (from backend/crypto_engine.py) aesgcm = AESGCM(encryption_key) # 256-bit key nonce = os.urandom(12) # fresh 96-bit nonce aad = f"securesearch:v1:record:{record_id}".encode() ciphertext = aesgcm.encrypt(nonce, plaintext, aad) # ciphertext includes 16-byte GCM authentication tag
🔑 HMAC-SHA-256 Search Tokens

What is Searchable Encryption?

HMAC tokens allow searching encrypted data without decrypting it. A keyed hash of each field value is stored instead of the plaintext. At query time, the same token is recomputed and matched.

AlgorithmHMAC-SHA-256
KeySeparate 256-bit SEARCH_KEY
Output64-character hex string
Domain sep.field prefix prevents cross-field collisions
Normalisationlowercase, strip, replace spaces with _
# Token generation (from backend/searchable_index.py) message = f"location:laboratory_a".encode() token = hmac.new(search_key, message, sha256).hexdigest() # → 64-char hex, stored in DB (never the plaintext value)
🪣 Numeric Bucket Indexing

Why buckets?

HMAC tokens are deterministic equality checks. For range queries (e.g. temperature > 30°C), the value space is divided into 1-unit buckets. Each bucket gets its own token. Range queries enumerate all relevant bucket tokens.

Temperature range-20°C to 80°C
Temperature bucket1°C width
Humidity range0% to 100%
Humidity bucket1% width
Post-decrypt checkExact comparison always applied
# Example: 30.7°C → bucket 30 # Query: temperature > 30°C # Buckets enumerated: 31, 32, 33, … 80 # Candidates fetched and decrypted # Exact check: value > 30.0 (not ≥ 30)
🔑 Key Management

Three separate keys

  • ENCRYPTION_KEY — AES-256-GCM encryption/decryption only
  • SEARCH_KEY — HMAC token generation only
  • INTEGRITY_KEY — HMAC integrity verification only

Keys are never stored in the database, never sent to the browser, and must never be committed to Git.

# Generate keys (run once): python scripts/generate_keys.py # Keys stored in .env file only: ENCRYPTION_KEY_B64=base64(32_random_bytes) SEARCH_KEY_B64=base64(32_random_bytes) INTEGRITY_KEY_B64=base64(32_random_bytes)
