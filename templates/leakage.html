⚠ This page is an honest academic analysis of what information the searchable encryption scheme leaks. Understanding leakage is essential for a correct threat model.
🛡️ Threat Model

Attacker Level 1 — Encrypted Storage Only

Attacker obtains only the encrypted object files from storage.

  • ✅ Cannot read sensor values
  • ✅ Cannot read device IDs
  • ✅ Cannot read locations
  • ⚠ Can observe object sizes and timestamps
  • ⚠ Can count the number of records

Attacker Level 2 — Storage + Token Index

Attacker obtains encrypted objects AND the database token index.

  • ✅ Cannot reverse HMAC tokens without search key
  • ⚠ Can observe equality patterns: records with identical field values share tokens
  • ⚠ Can count token frequencies
  • ⚠ Can observe search patterns if queries are logged
  • ⚠ Bucket tokens reveal approximate numeric ranges

Attacker Level 3 — Compromised Server

Attacker gains access to the Flask application server or the .env file.

  • ❌ Can read encryption key → decrypts all records
  • ❌ Can read search key → reverses token index
  • ❌ Can intercept plaintext during ingestion and decryption
  • → All data is exposed

🎓 Academic Contribution

What this project demonstrates

This project implements a Searchable Symmetric Encryption (SSE) scheme with controlled, documented leakage — not zero-leakage privacy. This is consistent with the academic literature on SSE schemes (SSE-1, SSE-2, etc.).

  • An honest IoT cloud storage system cannot guarantee zero leakage to the storage provider
  • The scheme protects sensor data from passive adversaries who obtain only the encrypted storage
  • The HMAC index leaks equality patterns — a known and accepted trade-off for search functionality
  • Numeric bucket indexing leaks approximate value ranges — a known trade-off for range search capability
  • Perfect privacy would require ORAM (Oblivious RAM) schemes, which have high performance cost
  • This system represents a practical balance between privacy and usability for an academic demo
ℹ️ For production use, consider: TLS-encrypted connections, server-side trusted execution environments, oblivious data access patterns, and proper secret management with HSMs.
