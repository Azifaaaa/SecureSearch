🔐 SecureSearch Cloud

Project Abstract

SecureSearch Cloud is an academic project demonstrating privacy-preserving searchable encryption for IoT sensor data in cloud storage. It was developed as part of an M.Sc. Cybersecurity programme.

The system simulates five virtual IoT sensor devices, encrypts every reading with AES-256-GCM before cloud upload, and allows authorized users to search the encrypted dataset using keyed HMAC-SHA-256 search tokens — without decrypting the entire database.

🎯 Key Features
  • AES-256-GCM authenticated encryption of all sensor records
  • HMAC-SHA-256 searchable encryption index (no plaintext in DB)
  • Numeric bucket indexing for range queries
  • Two-phase search: token lookup + post-decryption exact verification
  • Supabase cloud storage + PostgreSQL integration
  • Local mode (SQLite + filesystem) for development
  • 5,000-record synthetic dataset with 5 virtual devices
  • Integrity verification (SHA-256 + HMAC)
  • Real-time sensor simulation dashboard

🎓 For Your Professor

Simple explanation of the academic contribution

Traditional cloud storage stores data in plaintext or with simple encryption that prevents any searching. This project solves the "search over encrypted data" problem using a technique called Searchable Symmetric Encryption (SSE).

Every IoT sensor reading is encrypted with AES-256-GCM before it leaves the application. For each field that needs to be searchable (device ID, location, status), we compute an HMAC-SHA-256 "token" using a secret key. These tokens are stored in a database index. When a user searches, we compute the same token for the query value and look it up — without ever storing or searching plaintext sensor values.

For numeric range queries (temperature > 30°C), we use a bucketing scheme: the value space is divided into 1-degree buckets, each with its own token. We enumerate the relevant bucket tokens, find candidate records, decrypt them, and apply an exact numeric comparison. This prevents false positives from bucket boundary effects.

The system is honest about its limitations: an observer of the token index can see that some records share the same token (equality-pattern leakage), and bucket tokens reveal approximate value ranges. This is consistent with the academic SSE literature and is clearly documented in the Leakage Analysis page.
